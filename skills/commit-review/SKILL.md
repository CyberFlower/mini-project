# Commit Review

커밋을 하나씩 보며 사람이 설명할 근거가 없는 변경(의도 부채)과, 빠졌거나 검증 근거가 없는 동작(구현 부채)을 드러낸다. 보고는 대화창에만 하고 파일, 브랜치, 작업 트리, 인덱스를 바꾸지 않는다. 테스트도 실행하지 않는다.

## 시작

1. 범위: 사용자가 준 revision 범위나 개수를 쓴다. 없으면 현재 브랜치 HEAD에서 닿는 전체 커밋을 쓴다. 커밋되지 않은 변경은 보지 않는다.
2. 순서: 사용자가 오래된 순·최신순을 정하지 않았으면 다른 작업 전에 먼저 묻는다.
3. `git log --no-merges --format='%h %s'`로 목록을 만들고, 오래된 순이면 `--reverse`를 더한다. `번호. 짧은 해시 제목` 형식으로 보여준다.
4. 첫 커밋 하나만 보고하고 멈춘다. 사용자가 `다음`·`이전`·번호·해시로 고르면 그 커밋을 보고한다. 목록의 끝이면 더 없다고 알린다.

## 의도 출처

아래만 의도의 출처로 쓰고, 현재 작업 트리의 내용을 기준으로 찾는다.

- 커밋 메시지
- 커밋 메시지나 코드가 가리키는 요구사항 ID와 그 요구사항 문서
- `ARCHITECTURE.md`의 구조와 결정, 관련 Feature의 `IMPLEMENTATION.md`
- 프로젝트 지침(`AGENTS.md` 등)이 가리키는 그 밖의 요구사항·설계 문서

대화에서만 언급된 의도와 코드에서 추론한 의도는 출처가 아니다.

## 커밋 보고

`git show --stat <hash>`로 바뀐 범위를 보고 `git show <hash>`로 diff를 읽은 뒤, 아래 형식으로 짧게 보고한다.

```text
### <번호>/<전체> <짧은 해시> <제목>
- 의도: <출처에 적힌 의도> (출처: <커밋 메시지 | 요구사항 ID | 문서 경로> 또는 근거 없음)
- 핵심 변경: <실제 diff 기준, 의도 단위로 묶은 변경>
- 의도와 다른 점: <기록된 의도와 다르게 바뀌었거나 빠진 곳> 또는 없음
- 적혀 있지 않은 결정:
  - 왜 <선택>했나? (추정: <이유 후보>)
    <파일 경로>
    - <diff에서 그대로 옮긴 줄>
    + <diff에서 그대로 옮긴 줄>
- 테스트 시나리오:
  - <확인할 동작을 문장으로> — 검증 근거: <테스트 파일 | 검증 기록 위치> 또는 없음
```

- 핵심 변경은 파일별로 나열하지 않고 diff를 붙이지 않는다.
- 이유 후보는 반드시 `추정`으로 표시하고, 출처가 있는 의도처럼 쓰지 않는다. 적혀 있지 않은 결정이 없으면 `없음`으로 쓴다.
- 적혀 있지 않은 결정에는 그 선택이 담긴 diff를 파일 경로와 함께 `+`·`-` 줄로 최대 3줄 붙인다. 줄은 diff에서 그대로 옮기고 다듬지 않는다. 바꾸지 않은 것에 대한 결정처럼 보여줄 diff가 없으면 생략한다.
- 테스트 시나리오는 코드 없이 문장으로 쓴다. 검증 근거는 현재 작업 트리의 테스트, 또는 `IMPLEMENTATION.md`나 프로젝트 지침이 가리키는 검증 기록에서 찾는다. 근거가 있다는 것을 통과로 보고하지 않는다.
