# Toy Project Init

작은 프로젝트에 필요한 개발 규칙과 문서를 준비하고, 이후 작업에도 같은 지침을 적용한다. 사용자가 따로 지정하지 않으면 한국어로 작성한다.

## 초기 설정

1. 대상 프로젝트 경로와 요청 범위를 확인한다. 현재 폴더가 명확한 대상이면 다시 묻지 않는다. 적용되는 기존 지침, `AGENTS.md`, 세 문서와 프로젝트 구조를 먼저 읽는다. `Agents.md` 등 유사한 파일이 있다면 그 내용도 확인한다.
2. [개발 지침 원본](assets/development-guidelines.md)을 읽는다. 초기화만 요청했다면 개발 지침과 세 문서 설정까지만 수행한다. 앱 생성, 기술 스택 도입, 의존성 설치, Git 원격 생성·공개를 초기화에 포함하지 않는다. 추가 작업은 사용자의 별도 요청 범위에 따른다.
3. 중요한 요구사항이나 기존 규칙의 충돌은 관련 내용을 수정하기 전에 확인한다. 독립적으로 진행할 수 있는 부분은 계속한다. 확정되지 않은 내용을 요구사항이나 기술 결정으로 기록하지 않는다.
4. 프로젝트 루트 `AGENTS.md`에 원본 지침을 반영한다. 파일이 없으면 원본으로 생성한다. 기존 파일이 있으면 프로젝트 고유 지침을 보존하고 빠진 지침만 통합한다. 같은 지침이 이미 있으면 중복 삽입하지 않는다. 대소문자가 다른 기존 파일을 임의로 삭제하지 않는다.
5. 다음 역할에 맞춰 세 문서를 생성하거나 보완한다. 기존 내용과 결정, 검증 기록을 유지하고 현재 상태에 필요한 부분만 수정한다. 빈 양식을 덮어쓰지 않는다.

   | 문서 | 기록할 내용 |
   | --- | --- |
   | `REQUIREMENTS.md` | 확정 요구사항, 제약, 가정·미확정 사항, 확인 가능한 완료 기준 |
   | `DESIGN.md` | 선택한 아키텍처와 구현 방식, 선택 이유. 아직 근거가 없는 기술 결정은 미정으로 기록 |
   | `IMPLEMENTATION.md` | 구현 순서, 현재 진행 상태, 실제 실행한 검증과 결과, 남은 문제 |

   프로젝트 아이디어가 아직 없으면 개발 지침 초기화 범위만 기록하고 제품 요구사항은 미정으로 둔다. 초기 문서를 만들기 위해 제품 기능을 만들어내지 않는다. 같은 요구사항·설명·결과를 세 문서에 반복하지 않는다.
6. 생성·수정 파일을 실제로 읽어 원본 지침 누락, 기존 내용 손실, 중복, 문서 간 모순이 없는지 확인한다. 초기화 결과 확인과 제품 동작 검증은 구분한다. 코드를 구현했다면 실행과 관련 테스트를 수행하고, 실행하지 못한 검증은 이유와 함께 미실행으로 기록한다.
7. 변경 파일, 검증 결과, 중요한 미확정 사항을 간결하게 보고한다. 초기 설정만으로 제품 구현이나 테스트까지 완료했다고 보고하지 않는다.

## 이후 개발

이미 초기 설정된 프로젝트에서는 매번 문서를 다시 만들지 않는다. 기존 `AGENTS.md`와 세 문서를 읽고 원본 개발 지침을 현재 요청에 적용한다. 필요한 최소 변경을 구현하고, 주요 기능 구현 후 실제 실행·관련 테스트 결과를 `IMPLEMENTATION.md`에 반영한다. 요구사항이나 설계가 달라졌을 때 해당 문서도 함께 갱신한다.
