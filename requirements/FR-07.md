# FR-07: 커밋별 의도 부채·구현 부채 보고

개요: [요구사항](../REQUIREMENTS.md)

커밋 하나의 보고 항목, 의도로 인정하는 출처, 보고의 경계를 정한다.

## Acceptance Criteria

### 보고 항목

커밋 하나를 보고할 때 쓰는 항목이다.

| 보고 항목 | 내용 |
| --- | --- |
| 의도 | 출처에 적힌 의도와 그 출처. 출처가 없으면 `근거 없음` |
| 핵심 변경 | 실제 diff 기준으로 무엇이 바뀌었는지. 파일별로 나열하지 않고 의도 단위로 묶어 짧게 쓰며, diff는 붙이지 않는다 |
| 의도와 다른 점 | 기록된 의도와 다르게 바뀌었거나 빠진 곳. 없으면 `없음` |
| 적혀 있지 않은 결정 | 출처에 이유가 없는 선택을 `왜 ~했나?` 질문으로 쓴다. 이유 후보는 `추정`으로 표시한다. 그 선택이 담긴 diff를 파일 경로와 함께 `+`·`-` 줄로 최대 3줄, 다듬지 않고 그대로 옮긴다. 바꾸지 않은 것에 대한 결정처럼 보여줄 diff가 없으면 생략한다 |
| 테스트 시나리오 | 코드 없이 문장으로 쓰고, 시나리오마다 검증 근거(테스트 파일, 또는 `IMPLEMENTATION.md`나 프로젝트 지침이 가리키는 검증 기록의 위치)나 `없음`을 붙인다 |

### 의도의 출처

의도로 인정하는 출처와 인정하지 않는 출처다.

| 출처 | 포함 여부 |
| --- | --- |
| 커밋 메시지 | 포함 |
| 커밋 메시지나 코드가 가리키는 요구사항 ID와 그 요구사항 문서 | 포함 |
| `ARCHITECTURE.md`의 구조와 결정, 관련 Feature의 `IMPLEMENTATION.md` | 포함 |
| 프로젝트 지침(`AGENTS.md` 등)이 가리키는 그 밖의 요구사항·설계 문서 | 포함 |
| 대화에서만 언급된 의도, 코드에서 추론한 의도 | 제외 |

- 출처 문서와 검증 근거는 현재 작업 트리의 내용을 기준으로 찾는다.

### 보고의 경계

- 테스트를 실행하지 않으며, 검증 근거가 있다는 것을 통과로 보고하지 않는다.
- 보고는 대화창에만 하고 파일, 브랜치, 작업 트리, 인덱스를 바꾸지 않는다.

## 근거

- 이 스킬은 요약보다 설명할 근거가 없는 곳을 드러내는 데 목적을 둔다.
- 코드에서 추론한 의도는 늘 코드와 맞아 보여 의도 부채를 가린다. 그래서 출처를 붙이고, 출처가 없으면 `근거 없음`, 이유 후보는 `추정`으로 구분한다. 대화에서만 오간 의도도 기록이 아니므로 출처에서 뺀다.
- 적혀 있지 않은 결정에만 diff를 붙이는 이유: 결정이 코드에 실제로 있는지 바로 확인할 수 있고, 설명할 때 근거가 되는 줄을 짚을 수 있다. 핵심 변경은 여러 파일에 걸친 요약이라 3줄로는 대표성이 없고, 줄을 고르는 판단이 다시 들어가 오해를 부를 수 있다. 다듬은 줄은 확인용으로 쓸 수 없어 그대로 옮긴다.
- 출처를 현재 작업 트리 기준으로 보는 이유: 확인하려는 것은 지금 설명할 근거가 기록되어 있는지다. 커밋 이후에 기록한 이유도 근거로 인정한다.
- 결과를 문서에 남기지 않는 이유: 점검 결과를 `ARCHITECTURE.md` 등에 계속 쌓으면 문서가 길어져 오히려 읽기 어려워졌다. 기록할지는 사용자가 보고를 보고 정한다.
- FR-06에서 한 번에 한 커밋만 보고하는 이유: 범위 전체를 한 번에 요약하면 설명이 얕아지고 결과를 끝까지 읽지 않게 된다. 순서를 사용자가 고르게 한 것은 처음부터 흐름을 따라가는 경우와 최근 변경부터 보는 경우가 모두 있기 때문이다.
- FR-06에서 merge 커밋을 빼는 이유: merge 커밋의 변경은 함께 합쳐진 개별 커밋에서 이미 본다.
